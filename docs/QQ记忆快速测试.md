# QQ 记忆快速测试

比较多会话、时间更新、干扰事实和续聊时，另跑 [55 道扩展题](QQ记忆扩展测试.md)。两套题共用一个回放脚本。

## 只借鉴三件事

- 写入前拿少量相关旧事实给提取器参考，保留一套新增、确认、更正规则。
- 召回先过主体、有效期和删除检查，再用现有关键词和向量排序。商品型号、人名、游戏别名值得提高权重。候选还要能回答当前问的那个细节。
- 用带预期证据的固定题回放，分别检查已保存事实、实际注入和回复。反思沿用原话来源。

## 怎么记分

- **无用事实率**等于无用注入条目数除以全部注入条目数。以实际渲染给模型的条目为准，同义重复的第二条也算无用。
- **应空误注入率**等于本应为空但仍带事实的题数除以所有应空题数。
- **完整命中**统计每个有答案的题是否拿齐最小证据。即使无用事实率为零，也要用这一项检查漏召回。

## 一条命令重跑

在 `rin-memory` 仓库根目录运行，Node 需在 PATH 上。脚本读取上面的题表，在临时记忆根中运行 RIN `/v1/context` 的实现，再用相邻 `dsh-rin-memory` 仓库的渲染器统计实际带入。固定日期、1000ms 预算和两个测试主体，适合做前后比较。提取题可以单独用测试私聊回放。

```powershell
uv run --locked python tools/check_qq_memory.py --check --allow-missing Q06
uv run --locked python tools/check_qq_memory.py --case Q05 --case Q08 --json
```

`--dsh-root` 可指定渲染器目录。`--json` 提供 `selected`、`injected`、`extra` 和 `missing`，可直接保存或做差分。`--check` 同时检查多带和漏带。`--allow-missing Q06` 只放行已知的别名漏召回，结果仍会显示这题。

接手时先跑当前题单。定位多带时对照 `selected` 和 `injected`，前者是 RIN 入选，后者是 DSH 实际采用。新增场景直接在上表加行，`应选` 列只写回答所需的最小证据。原始用例的预期保留，便于和历史基线比较。

## 2026-11-11 基线

在服务器临时目录使用已安装的 RIN `0.1.0.dev24` 与 DSH RIN `0.3.16` 回放。召回使用当前的 1000ms 服务预算，先取 RIN 入选清单，再用 DSH 渲染实际注入材料。召回题评的是这份材料，提取题另用真实模型跑了正常提交和提取链路。

| 指标 | 结果 |
|---|---:|
| 无用事实率 | 4 / 11（36.4%） |
| 有无用事实的题 | 4 / 12 |
| 应空误注入率 | 1 / 5（20%） |
| 有答案的题完整命中 | 5 / 7 |

- Q01 问实付，多带了 K4 的轴。Q02 问轴，多带了 K2 的实付。
- Q04 问 10 月 30 日买的型号，多带了 K3 的后续买价。Q08 问消音原理，多带了 K4 的个人用轴记录。
- Q05 找到了办公室键盘和实付金额，漏了轴。Q06 没能把 COD 匹配到中文游戏名。
- Q09、Q10、Q11、Q12 为空。删除测试通过 RIN 删除入口移除了 D1。
- 提取只生成了 E01 的称呼和 E02 的购买事实。购买事实保留了型号、静音红轴和 299 元。E03–E05 没生成长期事实。
