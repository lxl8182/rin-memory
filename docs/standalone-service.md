# RIN 独立服务

本文维护启动、生命周期与服务合同。日常记忆行为见 [记忆流程](memory-flow.md)，客户端字段见 [HTTP 合同](webui-console.md#23-非宿主客户端合同)。

## 1. 服务职责

服务统一装配存储、模型、后台任务和 HTTP 接入。宿主以客户端方式读取或提交，不需要与核心共享进程。

## 2. 运行与写入所有权

### 2.1 日常运行

独立服务持有权威核心与同源水彩管理台，栈模板监听 `127.0.0.1:48931`。可选 N.E.K.O 宿主在其后启动，默认端口为 `48911`。工作区整栈命令和旧入口的端口边界见 [AGENTS.md](../AGENTS.md#3-运行与验证)。

### 2.2 单写者与恢复

可写入口先解析真实数据根，持有 `.rin_memory.root.lock`，再装配核心。互斥由操作系统文件锁决定，锁文件中的 PID 用于排查。启动先回放 journal 到持久视图，再允许接入和后台维护。关闭先拒绝新请求，排空在途工作并停止维护，最后释放根锁。只读管理入口可查看数据。

### 2.3 初始化与配置

通过 [README](../README.md#构建与启动) 初始化。`stack.toml` 内相对路径从配置文件所在目录计算；`runtime.python` 指定解释器，`runtime.package_version` 固定安装包版本。配置、核心数据、宿主数据、状态和日志分目录。空库从同源管理台创建角色并首次发布。

## 3. API 与整轮提交

### 3.1 入口

| 接口 | 职责 |
|---|---|
| `GET /v1/health` | 读存储、聊天与后台能力 |
| `POST /v1/context` | 读取本轮人格、约束、近期记录与可选记忆，签发范围和版本绑定的凭据 |
| `POST /v1/context/reserve` | 以稳定请求标识预约外部生成并持久保存依据 |
| `POST /v1/chat` | 服务生成并提交完整对话 |
| `POST /v1/turns`、`POST /v1/events` | 提交外部完成的轮次或来源事件 |
| `GET /v1/requests/{id}` | 查询或回放同作用域的提交结果 |
| `POST /v1/receipts` | 按生成、平台接受和显示等实际状态记录回执 |

### 3.2 身份和作用域

`clients` 授权角色范围、主体和可用能力。服务以认证身份建立 `client_id`，同时校验会话、场景和来源键。默认仅回环监听，HTTP 入口会校验 Host/Origin。QQ/DSH 的配置见 [插件说明](https://github.com/lxl8182/dsh-rin-memory)。

### 3.3 生成与降级

先读取固定人格版本、删除/更正依据和上下文，生成后复核依据再提交。可选记忆的筛选由 `summary` 档完成，聊天正文由 `conversation` 档或宿主生成。筛选失败时继续提供必需约束。`context.selection` 及预约/采用字段见 [客户端合同](webui-console.md#23-非宿主客户端合同)。

### 3.4 幂等、错误和恢复

- 同一请求重试复用首次 `request_id`、`source_key`、`occurred_at` 和业务内容。已提交结果直接回放；同键异内容返回冲突。
- 来源写入、原话视图和提取任务可以分步恢复。原话已落盘、提取任务缺失时，重试同来源补入缺失任务。整轮结果通过 journal 和持久视图提交。
- 过期或失效的上下文需重新签发。已失效的结果返回 410；预约可以在重启后复核屏障并用于该轮补交。容量满返回 429，已经提交的回放仍可用。
- 生成失败与待提取是不同状态。`committed` 表示整轮已持久提交；事实提取结果由后台另行产生。`used`、`sent`、`delivered` 分别表示采用、平台接受和实际显示或播放。

## 4. 模型和后台

### 4.1 模型适配

从 `models.service` 读取模型分档。`api_key_env` 填环境变量名；管理台保存的连接设置由服务状态目录中的 `model_config.json` 管理，公开状态和导出只给能力信息。模型适配器使用工作线程、并发槽和绝对调用截止时间。超时后请求可结束，实际网络工作结束时由线程释放槽位。

### 4.2 健康和暂停

`storage`、`chat` 和 `background` 分别报告。缺模型或凭据可影响生成与提取，存储管理仍可使用。瞬时超时、限流和传输错误可重试。

`service.memory_enabled=false` 在重启后暂停长期提取、召回、近期记忆补充和自动维护。普通聊天、发布人格和原话存档继续使用，已有事实及待处理队列保留。暂停期间的原话不会新增提取任务。

### 4.3 后台维护

服务启动后的维护周期由 `maintenance_interval_s` 控制，默认 60 秒。按配置执行 journal 恢复、outbox、反思、归档、成长、摘要和清理重试。管理台可查看步骤结果与积压。

## 5. 数据边界

### 5.1 原话、事实与适用范围

原始事件先进入来源与时间索引，事实按内容分类和证据规则另行产生。`scene` 保留原始发生场景，`applies_to` 控制使用范围。更正或删除写屏障后再处理缓存、派生项和客户端副本。

### 5.2 发布与回滚

服务版本以实际安装的 wheel 为准，DSH 以实际安装的 npm 包为准。用固定提交构建和手动安装，并核对运行能力。回滚沿用 `preserve_new` 合同，保留切换后新增的对话、更正和删除。
